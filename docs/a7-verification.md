原始证据位于忽略目录 `artifacts/a7/`：hardware.py、hardware.json、hardware.log、flash-final.log、各 profile 构建日志，以及 workbench-check.cjs/json/log 和 workbench-usb.png。密码只经授权的运行时管道交付 SDK，persist=false；没有写入源码、镜像或记录。

最终纳入计时的 60 条业务/管理请求均成功，失败率 0/60；不是底层 GATT RTT 或浏览器点击时延。普通连接计时样本 USB 1/1、WS 1/1 成功，分别 15.06、344.84ms。连接样本只有一次，不作为连接成功率的可靠估计。

- USB / WS 各写 GPIO13 十次，高低电平交替，最终 read 低电平并释放资源。
- USB / WS 各设置 1kHz、10bit PWM 的 25%、50%、25%、0%、100%；十次即时返回和随后独立 status 均与量化目标一致，errors=0，未再返回上一值。USB 另做 10Hz/14bit 两次变更，随后经 WS 在同一通道恢复 1kHz/10bit，创建和更新成功。未使用示波器，不证明物理波形精度。
- WS 同时建立两个 SDK 会话；第三个原始 WS 连接按容量关闭。关闭第一个会话后，新 SDK 会话连接成功，第二个会话仍可 ping。另五次 SDK WS 建连全部成功（双连接、槽位复用、两次异常帧后恢复），不视为五次独立冷连接试验。
- 原始 WS 空 TEXT、分片 TEXT 各一例均被关闭；每例后重新连接并 ping 成功。预期拒绝不计为业务请求失败。
- 最终样本未出现心跳失败、结果未知或非预期断连；未抓包统计空口丢包或消息丢失，不宣称长期稳定性。BLE / MQTT 本轮未重测，不能由 USB / WS 结果推定无线性能。
- 另一个同代码、提交前构建的成功短测保存在 hardware-before-final-build.json：WS GPIO 写 N=10 平均 54.15ms，最终构建为 90.00ms。两轮分别保存，不混合统计；可见 Wi-Fi 环境/省电等待仍有波动，不声称稳定达到 50ms。

## 排查中保留的失败

- hardware-attempt1.json/log：测试工具选择 1Hz/14bit/XTAL 40MHz，被底层驱动以 -1 拒绝；随后查询确认资源已释放。改用可运行的 10Hz。未在本次扩大 PWM 频率能力声明或更改时钟源，这个组合仍不能据宽范围参数提示认定可用。
- hardware-attempt2.json/log：新加入的初始占空比确认在低频→高频后预算不足，PWM open 返回 timeout。最初只按新 1kHz 周期计算预算，尚未合入 dev。
- hardware-attempt3.json/log：尝试在绑定后重设 duty，仍发生 timeout；该尝试未保留。最终 `562623a` 按切换前后较慢的实际周期确定预算，后续两轮同路径成功。不重放结果未知的写操作；各轮失败退出后先独立查询资源为零，再进入下一轮。
- 工作台首次无头脚本在后端尚未启动完时遇到 HTTP connection refused，发生于页面导航、尚无设备写入；后端监听就绪后重新执行通过。
- 第一次 server 全量 pytest 在安装 a7 wheel 前运行，doctor 版本校验一例失败；安装后重跑 162 项全部通过。
