# LIMIVIA 莉米维娅

连接数字世界与物理世界的本机硬件实验工作台。浏览器访问同源 Python 后端，后端通过 **limivia 0.3.0a3 / JSON-RPC 2.0 / 业务协议 v3** 连接合宙 CORE ESP32-C3 简约版，支持 USB、BLE、WebSocket 和 MQTT。界面沿用 MANAS 工作台关系与苍渊·白垣 Token，默认白垣。

设备契约必须为 `limivia-v3-jsonrpc2`；相同包版本或 protocol=3 本身不能证明兼容。旧 v1/v2、历史自定义 v3 不兼容。

## 安装与启动

开发环境使用 Python **3.12**、Poetry、项目内 `.venv`、Node.js 和 pnpm。

```bash
poetry env use python3.12
poetry install
pnpm --dir src/web install
pnpm --dir src/web run build
# SDK 按项目约定由 pip 单独安装已核验的 wheel。
poetry run python -m pip install /实际路径/limivia-0.3.0a3-py3-none-any.whl
poetry run python -m pip check
poetry run limivia-server doctor
poetry run limivia-server serve --port 8000
```

默认监听 `0.0.0.0:8000`。本机打开 `http://127.0.0.1:8000`，其他机器使用服务主机的 IP 访问；可通过 `--host` 或 `LIMIVIA_HOST` 覆盖监听地址。后端统一托管 `src/web/dist`；不需要长期运行第二个前端服务。VS Code 后端调试仍会先执行前端构建。

**SDK 按用户要求不写入 TOML、不由 Poetry 锁定，也不随仓库归档。** 先执行 Poetry 安装，再用 pip 安装 SDK。后续执行 `poetry install` 或 `poetry sync` 可能调整 SDK 所需的传递依赖，需再次执行 SDK 安装、pip check 和 doctor。doctor 显示实际版本、导入位置、契约与 pip 安装来源，不访问硬件。其他服务依赖继续使用 Poetry 和清华源。

本次使用的 SDK 来自独立 limivia 仓库 `dev` 提交 `7b3c1c3`，已合入业务说明中的升级；wheel SHA256 为 `cd6eb31703a6e63267dd2f865f3f7f33b4ccd970a5969e011b855a75b76653ed`。这是本次验证来源记录，不是运行时相邻目录依赖。

## 从连接到实验

1. 点击“连接设备”。USB/BLE 先搜索并明确选择服务主机候选；WS 填写 `ws://板卡IP/v3`；MQTT 填写 mqtt/mqtts URL 和完整目标 MAC。可使用预期 MAC 核对身份。
2. 连接后读取完整能力与一致状态，随后即可操作。设备工作台显示 profile、固件、协议和实际可用能力，完整 build/boot 在“固件详情”中查看。
3. 在“设备工作台”找到已接线的物理位置，点击引脚并选择功能。普通 GPIO 直接进入引脚实验，不必保存方案；UART、I²C、SPI 等先选当前引脚的角色，再补齐整组接线。记录的接线与供电位置不代表已检测到实物连接。
4. GPIO 选择数字输出后，点击“输出高电平”即可完成预检、创建和读回；首次低电平可在高级设置中选择。运行后同一按钮显示确认电平，点击切换；输入模式只读，开漏高电平表示释放。其他功能仍按保存方案、检查本组、应用本组操作，父总线先于子设备应用。修改配置不会自动替换已有运行资源。
5. 等待设备确认后调试真实资源；结束时明确关闭并核实释放。fault 仍占用引脚和控制器；“重试关闭”不会重新打开资源，父总线级联关闭会明确提示影响整树。

首页与外设调试已合并为 V5 板卡工作台：中央展示完整实物板图，侧栏展示接线组与未归组配置，右侧展示选择对象的配置和调试。板图常规高 480px，小窗口高 388px，窄屏重排为 288×388px，保留 13px 标签和 24px 引脚命中区。桌面默认完整显示板图，右栏身份及诊断入口固定，仅配置内容滚动；窄屏和放大时进入详情后可返回板卡。桌面标题与接线方案合并为一行，上方工具栏提供正反面、放大、引脚列表和按需图例。未确认板型不会套用本板映射。

GPIO 直接实验按模式显示必要字段，模式、上下拉等少量选项使用一个按钮循环切换。“高级设置”默认折叠，包含首次电平与驱动等参数，切换模式及折叠不会清空自定义值；更换引脚可在板图选择或取消，不自动关闭原实验。新建默认输入、无上下拉；选择输出时通过按钮明确确认首次高电平，旧方案保留原有值，缺省电平按设备默认低电平处理。PWM 保留 1000Hz、50%、10bit 默认及连续滑杆、精确输入和渐进配置，继续使用方案流程。

GPIO 可在实验前或运行后按需“保存到接线方案”。运行时保存设备确认配置和最近读回电平，同时关联已有资源，不重复创建；未运行时只保存待执行配置。保存时一并提交方案中的其他未保存修改，版本冲突保留本地实验记录。实验离开页面仍在运行，可从侧栏重新进入并显式“停止并释放引脚”；其他来源资源只读，点击模式替换动作后直接关闭并重建，不弹二次确认；未知结果不自动重试。

输入框、选择框和文本域统一使用 2px 圆角；白垣输入底色采用锁定的近白 `surface`（#FCFBF8），苍渊保留原输入底色。循环切换使用内容宽度的实体按钮、6px 圆角和选中底色，不带刷新图标。普通操作按钮、导航和卡片沿用原有形状。

GPIO 配置上方固定显示“设备当前状态”，区分设备确认的模式、最近读回的电平与下面的方案配置；板图工具栏同步显示选中引脚状态。可见页面共享后端每秒一次的只读观察，也可手动“读取状态”。本连接创建的输出资源在读回有效后，可用独立按钮切换实际电平，等待写入完成再读回；输入模式只读。开漏高电平表示释放，需外部上拉。未应用、断线、故障及结果待核实均明确提示；草稿和初始电平不代表当前实际输出。板载 D5 快捷面板保留专用状态与控制，避免重复显示一套按钮。

保护引脚在名称与彩色焊盘之间显示锁图标，不再使用斜纹或星号。仍可点击或用键盘选择，查看启动配置、Flash、系统灯或 USB 等具体保护原因；供电、接地、方案分配和普通资源占用不会显示保护锁。正反面、放大图与两主题采用相同规则。

已确认本板及 GPIO13 数字能力时，首次进入默认展开板载 D5 控制；之后保留用户明确选择。也可点击 D5 或 GPIO13 进入，可开关、呼吸演示、只读查询和关闭资源；D4 系统灯只读。GPIO13 绿色焊盘内有 LED 矢量符号，入场轻微呼吸三次，尊重“减少动态效果”设置；它用于定位，不表示真实输出。默认展开不会申请控制或写入设备。沿用最近确认输出与固定反馈区，普通快照刷新不会让全局文字闪烁。进行中任务数量在操作记录弹窗内查看。侧栏及浏览器标签页使用用户指定 Figma Logo 页的原始标志路径，字体随应用提供。

每台设备一份共享接线方案，保存在服务器 `wiring.sqlite3`。多个页面可编辑方案，旧版本保存会提示冲突并保留本地修改，可载入服务器版本或导出本地副本。保存方案和刷新页面不会应用配置；资源关联仍需本次启动与实例匹配。接口见 [共享方案说明](docs/wiring-plan.md)，设计与验证见 [同步记录](docs/figma-ui-audit.md)。

2026-10-24 的紧凑板图、合并图例和右侧功能家族已从 Figma 同步到应用，旧设计保留在历史归档。可用能力按电平与采样、通信、波形与定时分组；I²C、SPI、RMT 等多模式功能就地展开，每次只展开一个家族。内容来自当前设备实际能力；不可用功能及一致快照集中在诊断中按需查看。

- **离线流程**：编辑执行图、资源声明、变量及十类步骤，校验后导出或上传 `.flow.json`，再加载和启动。暂停不清输出，流程完成仍可能占用资源；停止清理、移除加载项、删除文件是不同动作。默认手动启动。
- **联网通信**：板上 Wi-Fi、MQTT、ESP-NOW 与服务主机控制传输分开配置。凭据仅写入，不回显或写入操作记录；MQTT queued 和 ESP-NOW MAC ACK 都不是远端应用确认。
- **设备维护**：诊断、系统状态、低功耗、缓存、组操作、OTA 和明确确认的持久数据清理。OTA 上传到非活动槽，commit 默认不重启；上传成功不代表新固件已运行。需要重启时由用户显式执行，之后重新核对身份。

连续 ADC、RMT、I²S 等结果保留长度、格式、序号及丢弃信息，可下载原始字节。没有真实数据时不绘制示例测量，不把连续 ADC 当 PCM，也不声称自动识别外接器件。

## 多页面、停止与恢复

后端一次管理一台设备，所有页面共享同一连接及本连接创建的资源，连接后即可操作。SDK 自动协调设备协议令牌，页面无需取得、释放或接管控制。页面刷新、关闭或实时通道恢复不会自动重放命令、停止实验或断开设备。

普通业务操作通过 a3 高层资源对象执行，记录从“执行中”进入确认后的终态，不编造 request/job 编号。显式 Job 与高级批量保留真实编号和作业状态；取消等待不代表设备取消。超时、断线和 response_capacity 不自动重试写操作。

“停止所有实验”影响所有来源并持久抑制自启，走独立通道。只有设备清理和持久化确认后才显示完成；失败保留错误与占用。“结束实验并断开”会由 SDK 清理本连接创建的资源；其他来源的资源不认领、不释放。清理未确认时明确提示输出可能仍在运行。浏览器刷新或关闭不会触发资源释放。

任务保存在 SQLite，默认目录为 `$XDG_DATA_HOME/limivia-server`，未设置时使用 `~/.local/share/limivia-server`，保留最近 30 天、最多 10,000 条已结束记录。服务重启将未确认任务标记为未知，不自动连接或申请控制；已知 job 可在同设备同 boot 下显式查询，新 boot 的旧句柄不可复用。

后台状态同步按最近一次成功的完整分页耗时调整等待预算，避免 BLE 多页读取超过 3 秒时反复误报引脚未知。前台操作期间暂停新增后台观察查询；写操作先等待已有快照读完，全局停止保留独立入口。真实读取失败或连接中断仍标记待核实，操作结果未知时必须先查询设备，不能直接重发。

```bash
poetry run limivia-server serve --data-dir ./data-bin/workbench --job-timeout 300
```

对应环境变量为 `LIMIVIA_HOST`、`LIMIVIA_PORT`、`LIMIVIA_DATA_DIR`、`LIMIVIA_JOB_TIMEOUT`。作业跟踪超时不是设备取消。设备管理使用单进程、单 worker；本机数据目录通过进程锁协调。当前没有远程账户系统，按本机工作台部署。

## 板卡与工程边界

板卡使用 3.3V 逻辑，外设共地。GPIO13 接板载 D5 LED；原生 USB、Flash 和保护脚以本次能力发现及设备预检为准。GPIO0/1/3/4 的数字与 ADC 互斥不等于永久禁用数字用途。

“引脚与占用”保留 32 个实物排针、正反面和键盘放大查看；点击板图只观察，不发送设备命令。供电脚不能作为 GPIO 电压容限依据。

SDK、ESP-IDF 固件及烧录工具各自独立维护。服务运行不依赖其检出位置。本轮同时修复 SDK 通知缺口判断、固件通知突发缓冲及服务状态恢复；各仓库分别构建验证。当前集成协议及冻结来源见 [协议](docs/protocol.md)，SDK 桥接和接口见 [后端模型](docs/backend-control.md)，旧客户端迁移见 [迁移说明](docs/migration-v3.md)。

### 引脚状态与稳定控制

板图使用 18px 图形符号表达状态：空闲留白，箭头相对板子表示输入/输出，实心和空心表示设备读回的高/低电平，PWM 与 ADC 使用对应波形。未知状态使用未知图标，不把初始配置当作实际电平；总线等其他功能的完整模式可选中引脚查看。保护锁、电气类别和 D5 定位符号分别表达不同含义；正反面及窄屏保持同一规则。工具栏“图例”提供符号说明，常驻图例与逐脚状态小字已移除。

有可见工作台时后端约每秒共享读取一次，多个页面不增加读取循环，隐藏或关闭后暂停；不申请控制权、不消费外设事件队列，也不增加操作记录。引脚读数按连接、设备、boot 和资源实例隔离。高低切换保留确认值与主按钮尺寸，正常处理中不插入小字，不改变右栏高度；只在失败或操作受阻时显示说明。

点击板图上已有 GPIO 的引脚，会直接进入实验面板。模式按钮立即可见；输入模式只读取电平，切为数字输出后主按钮明确显示将输出的高/低电平，执行后同一按钮显示已确认电平并可继续切换。“选择其他功能”可回到 PWM、总线等功能目录。LED 模式切换、GPIO 配置替换、单个资源关闭、释放引脚、保存记录和从方案移除不再弹浏览器确认。

用户明确选择取消所有二次确认：停止全部实验、断开连接、级联关闭、删除/格式化、固件上传、联网重配置与自动启动等均由按钮直接执行。维护操作不再要求手动输入确认文字，浏览器按所选操作自动附加后端协议要求的确认参数；后端校验、设备确认、错误反馈与禁止写入自动重试仍保留。
